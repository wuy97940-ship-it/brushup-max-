# 题库迭代与跨端质检机制

## 一次迭代的输入与产出

任务开始时明确内容范围、原题和存档保护、公开范围及验收标准。内容修改后，形成可复跑的内容生成入口、独立质量报告、冻结文件清单及可回退版本。运行结束、自动检查、人工或真机验收和发布是独立阶段。

私有资料解析由维护者在自己的私有库执行：原文件按册归档并核对SHA-256；逐页对账；以册次、章或专题、题块、题型、原题号定位。跨页数据、表格和公式必须恢复。候选只能进入正式入库、重复记录或待核对，缺页不能猜题。公开仓库接收独立原创内容及通用程序。

## 答案与讲解

每道题保留题干、选项、答案、原解析。新增讲解提供考点、原理、公式及适用条件、逐项或逐步分析、单位精度、易错点和记忆提示。扩展解析不能覆盖原解析。

计算题按小问保存过程与关键数值。明确单位，支持元与万元、百分比与小数换算；精确整数严格核对，舍入值容差为最后一位半个单位。没有精度要求时使用参考答案精度；歧义内容使用过程自评。首答统计保持，纠错练习单独记录。

数值模型从题目原始参数独立计算，不调用题库生成器的答案函数。结构和全量可确定数值自动检查；需要阅读判断的题目按章节、题型、计算风险和来源分层抽查。记录样本与实际发现，不将抽查表述为整库人工保证无错。

## 数据身份与存档

题目稳定ID、题库ID、题库家族、版本身份指纹和完整内容SHA分别保留。私人地图与公开原创版的历史指纹约定不同，公开版保留既有身份，不套用私人版的题号集合哈希。指纹保护地图和迁移，内容SHA识别同ID内容修订。追加迁移只允许已登记历史指纹与完整旧地图，不接收只改指纹的伪造地图。

保存采用临时文件和原子替换，或完整存档的一次原子提交。奖励和抽奖候选在失败重试期间保持；再点击领取、建设或结算得到同一结果。测试使用隔离存档。各端进度独立，跨题库备份拒绝导入。

## 跨端、候选与公开导出

内容主库经脚本生成桌面、微信及Expo数据，字段逐项比较。共用配置按照实际加载的覆盖关系检查；共用代码与素材逐文件核验。微信分包按完整关卡组合，不截断一场挑战。

冻结候选后，验收报告绑定它的SHA和源摘要；改动后生成新的候选，旧报告保留。实际上传包要确认所有必要资源，不能用模拟器显示或源码目录体积替代上传包完整性。平台不接收某种图片格式时，生成明确登记参数的兼容派生文件；原件保留，有损派生不称无损。

公开导出采用来源白名单，再检查题库原创身份、解码后的完整内容、凭据、本机路径、存档和大文件。`.gitignore`是辅助，不能替代扫描、压缩包复核及Git已跟踪文件核对。

## 阶段与持续记录

生成候选→契约与数值→界面/实际构建→冻结→实际包资源→上传→体验→隐私及提审→代码审核→备案→正式发布。每一项保存版本、时间、摘要和证据；发布前读取官方实际状态。公开联系方式、扫码、实名与费用需要真实前置条件时联系维护者。

当前事实与操作入口保持简短，历史报告和失败证据归档。执行耗时、外部等待、返工和必要用户介入分别记录；Token及费用未知时留空。暂停或中断后从最后一个已验证阶段继续。
