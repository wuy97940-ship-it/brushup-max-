# 发布步骤

1. 确认公开主库、稳定题号、原解析与完整小问字段。运行内容同步、公开扫描、独立答案模型和各端契约。
2. 对改动范围执行桌面界面、网页类型/lint/导出及离线/备份恢复，微信使用自己的开发者工具和AppID验证真实控件、跨分包和实际编译资源。手机结果单独登记。
3. 冻结源文件清单及SHA；生成新版本，不覆盖已交付的旧包。公开原版和私人版的程序与存档分别保存。
4. 网页将本次dist部署到自己的HTTPS入口，核对实际文件摘要、离线缓存及旧缓存更新。Expo的原生导出是代码候选，签名IPA与真实设备验收另记。
5. 微信先核对官方实际上传的开发版、时间、包体和必要资产，再配置体验路径。保存体验码及回执，填写版本描述、无需登录等真实信息和实际调用接口对应的隐私用途。
6. 公开隐私联系方式由维护者明确配置；提交协议后重新加载核对。常规提审成功后，在官方版本管理确认目标版本的审核记录，不重复提审在审版本。
7. 代码审核和备案均实际通过后发布；保存官方上线版本、时间与回退入口。任何拒审、真实登录前置或费用都单独记录，不把其它阶段通过当作发布完成。

本公开仓库使用体验配置和独立示例包名，没有绑定维护者的生产账号或后台会话。部署和GitHub Actions是否真正成功以对应平台的实际回执为准。
